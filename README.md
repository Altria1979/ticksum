# TickSum

**Know where your browsing time goes — and turn it into useful reports.**

TickSum 是本地优先的 Chrome 扩展：自动记录前台网页活动，在获得站点授权后提取正文，将筛选后的记录整理为可编辑、可复制的报告。

[隐私政策 / Privacy policy](docs/privacy-policy.md) · [Chrome 商店发布资料](docs/chrome-web-store.md)

目前为开发预览版，尚未在 Chrome 网上应用店发布。可从 [GitHub Releases](https://github.com/Altria1979/ticksum/releases) 获取预览安装包，解压后按下面的步骤加载。

## 已实现

- 自动记录 HTTP(S) 前台标签页；切换窗口、系统闲置、暂停时停止计时。
- 最近 X 小时、今天和自定义时间范围；按关键词、网站、标签筛选。
- 页面时长、网站汇总、时间分布、页面选择、标签与个人备注。
- 按站点授权的正文自动采集，Readability 与文档区域提取，SPA 导航识别。
- 本地正文快照、内容去重与历史时点关联。
- 时间复盘、学习记录、工作总结、调研记录四种离线报告。
- 报告编辑、保存、复制、Markdown 下载、统计 CSV 导出。
- 暂停、排除网站及子域名、闲置阈值、保留期、撤销正文权限、删除本地数据。

首版不包含 AI 摘要、账号、云同步或平台自动推送。报告中的内容来自带来源的正文摘录和个人备注，不会推断用户已经掌握某项知识。

## 开发

需要 **Node.js 22.12+，推荐 Node.js 24**。仓库提供 `.nvmrc`。依赖使用 npm 锁文件。

```sh
git clone https://github.com/Altria1979/ticksum.git
cd ticksum
nvm use
npm ci
npm run dev
```

开发模式由 WXT 启动测试浏览器。生产构建和打包：

```sh
npm run build
npm run zip
```

在 Chrome 的 `chrome://extensions` 打开开发者模式，选择“加载已解压的扩展程序”，加载 **`.output/chrome-mv3`**。点击扩展图标打开统计页。

首次安装没有历史数据，也不会立即采集。打开 TickSum 阅读数据用途说明，点击“启用自动记录”后，正常浏览网页即可产生记录。到“设置 → 正文采集授权”输入网站地址并授权，再切回网页，即可自动采集已加载正文。首用确认只需完成一次，日常无须手动开始或结束计时。

未完成首用确认的旧安装也会暂停采集，原有数据保留。记录、正文、备注和报告保存在本机浏览器中；当前版本未提供应用层静态加密，不能抵御本机账户或浏览器配置目录被读取。详见隐私政策。

## 独立界面预览

```sh
npm run preview
```

- `http://127.0.0.1:5173/`：真实空状态的界面预览。
- `http://127.0.0.1:5173/?demo=1`：明确标注的示例数据，便于体验筛选和报告。

预览模式不执行浏览器采集，演示记录和编辑仅保存在内存中，刷新后重置。扩展模式使用 IndexedDB 持久化，不载入示例数据。

## 数据与计时口径

- 每个活动片段保存页面、起止时间；统计按查询边界裁剪，并对重叠时间去重。
- 30 秒检查点用于持久化。扩展后台恢复时幂等重放未完成写入；超过 60 秒没有检查点的未知空档保守舍弃，不补算休眠时间。
- 默认 300 秒无系统操作后暂停，可设为 60–3600 秒。静态阅读可能被判闲置；时间是前台活动估算，不是精确阅读或理解指标。
- 默认保留 30 天活动与正文，可设为 1–365 天。**个人备注及已保存报告独立保留**；报告可能含有已经超过正文保留期的摘录。删除报告或“删除全部本地数据”才会移除它们。
- 排除网站、撤销授权和暂停会阻止新采集，已有记录不会因此立即删除。
- 不读取安装前的浏览历史，不记录隐身窗口、Chrome 内部页或扩展自身页面。后台播放音视频不另外累计时长。
- URL 保留查询参数和 hash，以区分文档与 SPA 路由；用户名密码字段移除。记录和导出可能包含网站 URL 中的业务参数，请按需要设置排除网站。

## 正文边界

正文提取只发生在已授权、当前前台且未被排除的网站。动态文档、虚拟列表、未加载段落、PDF、Canvas 和视频无法保证全文提取。快照明确标记“部分内容”或“完整度未知”，不会自动滚动或抓取整个知识库。

提取会移除表单输入、可编辑区域以及常见代码编辑器容器。复杂网站仍可能需要专门适配；敏感网站建议直接排除。只处理顶层页面，不读取跨域 iframe。

## 验证

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

`check` 包含 TypeScript、ESLint、Vitest 和生产构建。测试使用 Node 24。Playwright 固定为 1.56.1，以兼容当前 macOS 13 开发环境。

端到端测试使用一次性 Chromium 用户目录，不修改日常 Chrome 配置。正文集成测试仅给扩展的临时副本预授权 `http://127.0.0.1/*`，验证真实注入、SPA 与采集边界；发版 manifest 保持网站权限可选。原生权限确认弹窗、真实系统锁屏与休眠需要实机补充检查，单测并不替代这些系统行为验证。

## 项目结构

```text
entrypoints/          Chrome 后台、正文脚本、统计页入口
src/shared/           数据与消息契约
src/tracking/         纯计时状态机、页面身份
src/extraction/       页面清理、正文提取、内容指纹
src/platform/         Chrome 设置
src/data/             Dexie 存储与保留期
src/analytics/        区间分析与聚合
src/reports/          报告模板、Markdown / CSV
src/ui/               React 页面与独立演示模式
tests/                单元、集成与端到端测试
docs/                 实现范围与界面参考
```

依赖按用途保持分离：WXT 管理扩展，React 管理界面，Dexie 管理结构化数据，Readability 提取文章，统计与报告生成是独立的 TypeScript 模块。
